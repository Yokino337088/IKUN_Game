# 剧情演出框架使用说明

## 一、这是什么

剧情演出框架是一个用于**2D游戏意识流剧情实时演算**的系统。简单说，它让你像导演一样，通过编排"命令"来控制画面上的角色、镜头、特效、文字、音乐等元素，组合成一段充满情绪张力的剧情演出。

**和传统对白系统的区别：**

| | 传统对白系统 (StoryPlayer) | 剧情演出框架 (PerformanceDirector) |
|---|---|---|
| 表达方式 | 纯文字逐句显示 | 文字+画面+镜头+特效+音乐同步演出 |
| 适用场景 | 日常对话、信息交代 | 关键剧情、情绪爆发、意识流段落 |
| 控制粒度 | 只控制文字 | 控制角色、镜头、滤镜、粒子等一切画面元素 |

---

## 二、框架结构

框架由 6 个文件组成，各自职责清晰：

```
剧情演出/
├── EPerformanceCommandType.cs    ← 命令类型枚举（22种）
├── PerformanceCommand.cs         ← 单条命令的数据结构
├── PerformanceSceneData.cs       ← 一幕演出的完整数据（ScriptableObject）
├── PerformanceDirector.cs        ← ★核心★ 演出总导演，解析并执行命令
├── PerformanceCharacter.cs       ← 角色控制器（显隐/移动/表情/震动）
├── PerformanceCameraController.cs← 摄像机控制器（震动/缩放/平移/旋转）
└── PerformanceEffectManager.cs   ← 特效管理器（滤镜/淡入淡出/模糊/闪白/粒子）
```

### 工作流程

```
你在Inspector中编辑 PerformanceSceneData（策划配置）
              │
              ▼
PerformanceDirector 读取它，按顺序执行每一条命令
      │
      ├──→ PerformanceCharacter      控制角色
      ├──→ PerformanceCameraController 控制镜头
      └──→ PerformanceEffectManager    控制特效
              │
              ▼
      外部事件回调（事件委托）
      → UI层显示文字 / 关卡逻辑响应
```

## 三、核心概念

### 3.1 命令（PerformanceCommand）

命令是演出的**最小执行单元**。每条命令就是一个动作，比如"显示对话"、"摄像机震动"、"画面变红"、"等待1秒"。

所有命令共用同一个数据结构，通过 `type` 字段区分类型。你在 Inspector 中只需要填写当前命令类型会用到的字段，其他字段保持默认值即可。

每条命令都有以下通用参数：

| 参数 | 说明 |
|------|------|
| `duration` | 持续时间（秒），动画类命令的过渡时间 |
| `delay` | 延迟（秒），上一条命令结束后等多久再执行本条 |
| `timestamp` | 触发时间戳（秒），>0表示从演出开始后第N秒触发。**BGMDriven模式专用** |

### 3.2 演出场景（PerformanceSceneData）

一出演出就是一个 ScriptableObject 资产。它包含：
- **场景信息**：章节编号、模块编号（方便代码查找）
- **同步模式**：`Sequential`（顺序）或 `BGMDriven`（BGM驱动）
- **主BGM设置**（BGMDriven模式）：演出的"主题曲"，演出总时长默认跟随歌曲长度
- **初始设置**：开场背景图、开场BGM
- **命令序列**：一条条命令从上到下排列

命令**从上到下顺序执行**，执行完一条再执行下一条。但在 BGMDriven 模式下，设置了 `timestamp` 的命令会按照时间戳触发，不受列表顺序约束。

### 3.3 Parallel 命令（并行组）

`Parallel` 命令可以让**多个子命令同时执行**。这是意识流演出的关键——你可以在同一时间让"文字显示 + 画面变红 + 镜头拉近 + 角色震动"同时发生。

### 3.4 两种演出模式

| | Sequential（顺序模式） | BGMDriven（BGM驱动模式） |
|---|---|---|
| 驱动方式 | 命令列表从上到下执行，执行完即结束 | 以一首歌为时间轴，命令可按秒数定时触发 |
| 适合场景 | 短小精悍的意识流片段（5~30秒） | 一首歌 + 一整段剧情（3~5分钟） |
| 命令编排 | 按发生顺序排列即可 | 设置 `timestamp` 精确控制触发时刻 |
| 结束条件 | 所有命令执行完毕 | BGM播放完毕 + 所有命令执行完毕 |
| 进度展示 | 不支持 | 支持进度条（`OnBGMProgress` 事件） |

## 四、22 种命令详解

### 文字类

| 命令 | 说明 | 关键参数 |
|------|------|----------|
| **Dialogue** | 显示对话文字 | `speakerName`（说话人）、`textContent`（内容）、`duration`（停留时间） |
| **FloatingText** | 飘散文字 | `textContent`（内容）——文字会在屏幕随机位置出现，这是意识流的标志性效果 |

### 角色类

| 命令 | 说明 | 关键参数 |
|------|------|----------|
| **CharacterVisibility** | 显示/隐藏角色 | `characterName`、`characterVisible`（true=显示）、`duration`（淡入淡出时间） |
| **CharacterMove** | 移动角色 | `characterName`、`characterTargetPos`（屏幕坐标0~1）、`duration` |
| **CharacterExpression** | 切换表情/姿态 | `characterName`、`characterSpriteName`、`characterSpriteABName` |
| **CharacterShake** | 角色震动 | `characterName`、`shakeIntensity`（强度）、`duration`（时长） |

### 场景/背景类

| 命令 | 说明 | 关键参数 |
|------|------|----------|
| **BackgroundChange** | 切换背景图 | `backgroundSpriteName`、`backgroundSpriteABName`；有`duration`时会自动淡出→换图→淡入 |
| **BackgroundScroll** | 背景滚动 | `backgroundScrollDir`（方向）、`backgroundScrollSpeed`（速度）、`duration` |

### 镜头类

| 命令 | 说明 | 关键参数 |
|------|------|----------|
| **CameraShake** | 摄像机震动 | `cameraShakeStrength`（强度）、`cameraShakeVibrato`（频率）、`duration` |
| **CameraZoom** | 缩放 | `cameraZoomTarget`（目标正交大小，默认5）、`duration` |
| **CameraPan** | 平移 | `cameraPanOffset`（世界坐标偏移量）、`duration` |
| **CameraRotate** | Z轴旋转 | `cameraRotateAngle`（度数，5°=微倾，15°=明显倾斜）、`duration` |
| **CameraReset** | 恢复初始 | 无需参数，一切归位 |

### 特效类

| 命令 | 说明 | 关键参数 |
|------|------|----------|
| **ScreenColorFilter** | 全屏颜色滤镜 | `screenFilterColor`（颜色+透明度）、`duration` |
| **ScreenFade** | 淡入/淡出 | `screenFadeAlpha`（0=透明 1=全黑）、`duration` |
| **ScreenBlur** | 画面模糊 | `blurStrength`（0~10）、`duration` |
| **ParticleEffect** | 生成粒子 | `particleResName`、`particleABName`、`particleSpawnPos` |
| **Flash** | 闪白/闪黑 | `flashColor`（白=闪白 黑=闪黑）、`duration` |

### 音频类

| 命令 | 说明 | 关键参数 |
|------|------|----------|
| **PlayBGM** | 播放BGM | `audioResName`、`audioABName` |
| **StopBGM** | 停止BGM | 无需参数 |
| **PlaySFX** | 播放音效 | `audioResName`、`audioABName` |

### 控制类

| 命令 | 说明 | 关键参数 |
|------|------|----------|
| **Wait** | 等待N秒 | `duration`（秒数） |
| **Parallel** | 并行执行组 | `parallelCommands`（子命令列表） |
| **WaitForInput** | 等待玩家点击 | 无需参数，点击/按键后继续 |

## 五、在 Unity 中使用（操作步骤）

### 步骤一：创建演出场景资产

在 Project 窗口中，右键点击你想存放的位置，选择：

```
Create → 剧情演出 → 演出场景
```

这会在项目中生成一个 `.asset` 文件。选中它，在 Inspector 中可以编辑：

1. 填写 **场景名称**（如"回忆闪回_第一章"）
2. 设置 **章节编号** 和 **模块编号**
3. 可选：设置 **初始背景**（填写 AB包名 和 Sprite资源名）
4. 可选：设置 **初始BGM**
5. 在 **命令序列** 中添加命令，逐条配置参数

### 步骤二：在场景中搭建演出系统

创建一个空 GameObject，命名为 `PerformanceSystem`，然后挂载以下组件：

#### 1. 创建角色节点

```
PerformanceSystem/
├── Characters/              ← 角色根节点
│   ├── 主角                 ← 挂载 SpriteRenderer
│   ├── 配角A                ← 挂载 SpriteRenderer
│   └── 配角B                ← 挂载 SpriteRenderer
├── Effects/                 ← 特效根节点
└── UI/
    └── FilterOverlay        ← 全屏覆盖Canvas
```

#### 2. 挂载脚本

在 `PerformanceSystem` 上挂载脚本：

| 脚本 | 挂载位置 | 说明 |
|------|----------|------|
| `PerformanceDirector` | PerformanceSystem | 核心控制器 |
| `PerformanceCharacter` | PerformanceSystem | 角色管理器 |
| `PerformanceEffectManager` | PerformanceSystem | 特效管理器 |
| `PerformanceCameraController` | 主摄像机上 | 摄像机控制器 |

然后在 `PerformanceDirector` 的 Inspector 中设置引用：

- `characterController` → 拖入 `PerformanceCharacter` 组件
- `cameraController` → 拖入 `PerformanceCameraController` 组件
- `effectManager` → 拖入 `PerformanceEffectManager` 组件
- `backgroundRenderer` → 拖入背景图的 SpriteRenderer
- `sceneData` → 拖入你创建的演出场景资产

#### 3. 配置 PerformanceCharacter

在 `PerformanceCharacter` 的 Inspector 中：
- `characterRoot` → 拖入 `Characters` 节点
- `characterPrefabs` → 拖入各个角色 GameObject

#### 4. 配置 PerformanceEffectManager

在 `PerformanceEffectManager` 的 Inspector 中：
- `filterOverlay` → 拖入全屏覆盖的 UI Image（需要在Canvas下创建一个全屏Image）

### 步骤三：启动演出

**方式一：Inspector 直接播放**
在 `PerformanceDirector` 中拖入 `sceneData`，勾选 `Play On Start` 或者代码调用 `Play()`。

**方式二：代码调用**
```csharp
// 获取组件并播放指定场景
var director = GetComponent<PerformanceDirector>();
director.PlayScene(mySceneData);
```

## 6.5、长剧情演出（BGMDriven 模式）

这是框架最强大的功能——**播放一首歌，在这首歌的时间内完成一整段剧情演出**。适合关键剧情段落、角色独白MV、回忆杀等需要长时间沉浸式体验的场景。

### 核心思路

想象一下：你有一首3分30秒的歌。你希望：
- 0~10秒：画面从黑屏淡入，角色登场
- 10~45秒：第一段对白，配合舒缓的运镜
- 45秒：**恰好歌曲进副歌**——画面闪白，镜头拉近，特效全开
- 45~90秒：副歌段落，激烈的画面效果
- 90~180秒：第二段对白，情节推进
- 180秒：歌曲进入尾声，画面慢慢变暗
- 210秒：歌曲结束，演出收尾

BGMDriven 模式就是为这种需求设计的——你只需要在每一条命令上填 `timestamp`（触发秒数），框架会在演出开始后自动计时，到了指定的秒数就触发对应的命令。

### 在 Inspector 中配置

创建一个演出场景资产后，在 Inspector 中做以下设置：

#### 1. 切换到 BGMDriven 模式

在 `演出同步模式` 下拉框中选择 **`BGMDriven`**。

#### 2. 设置演出主BGM

| 字段 | 值 | 说明 |
|------|-----|------|
| `performanceBGMResName` | 你的歌曲资源名（如 `"回忆主题曲"`） | AB包中的AudioClip名 |
| `performanceBGMABName` | AB包名（如 `"music_four"`） | 歌曲所在的AB包 |
| `performanceBGMVolume` | 0.0~1.0（默认0.8） | 主BGM音量 |
| `performanceDuration` | 歌曲秒数（如 `210`） | 演出总时长（秒）。填0则演出在所有命令完成后才结束 |

> **重要**：`performanceDuration` 最好填歌曲的实际秒数，这样框架才能正确显示进度条，也能确保歌曲结束时演出同步结束。

#### 3. 编排命令——设置 timestamp

在命令序列中每添加一条命令时，填写 `timestamp` 字段：

| timestamp 值 | 含义 |
|---|---|
| `0`（或不填） | 顺序执行命令，在前一条之后紧接着执行（适合开场铺垫） |
| `>0`（如 `45`） | 时间戳命令，在演出开始后第N秒触发（精确到秒，可与歌曲节拍对齐） |

**典型编排模式：**

```
演出开始（BGM起）
  │
  ├─ t=0    ScreenFade(α=0→1, duration=2)   ← 开场淡入
  ├─ t=2    Dialogue("第一句台词", duration=3)  ← 顺序命令紧跟淡入
  ├─ t=5    Dialogue("第二句...", duration=4)  ← 继续对话
  ├─ t=10   BackgroundChange("场景B")         ← t=10秒切换背景
  ├─ ▶ t=45  Flash(白色闪)                     ← 副歌冲击！精确卡点
  ├─ ▶ t=46  CameraZoom(拉近), CameraRotate(微倾) ← 副歌镜头效果
  ├─ ▶ t=48  Parallel{FloatingText×3}          ← 碎片文字涌现
  ├─ ▶ t=90  ScreenColorFilter(暖黄, dur=2)    ← 过渡到第二段
  ├─       Dialogue("第三句...", duration=3)    ← 第二段对白（紧跟滤镜后）
  ├─ ▶ t=180 CameraReset, ScreenFade(α→1)      ← 尾声渐暗
  └─ t=210  演出结束（随BGM结束自动收尾）
```

### 进度条对接

BGMDriven 模式下，框架每帧向外报告演出进度。你可以接一个 UI 进度条：

```csharp
var director = GetComponent<PerformanceDirector>();

// 监听BGM进度（秒数 → 百分比）
director.OnBGMProgress += (elapsed, total) =>
{
    float percent = total > 0 ? elapsed / total : 0f;
    progressBar.fillAmount = percent;       // UI进度条
    timeLabel.text = $"{elapsed:F0}s / {total:F0}s";  // 时间显示
};

// 也可以在任意时候查询
float currentTime = director.PerformanceElapsedTime;
float totalTime = director.PerformanceTotalDuration;
```

### BGMDriven 模式的注意事项

1. **`timestamp` 命令不受列表顺序约束**：两条 timestamp 命令分别设定 `t=45` 和 `t=20`，第二条会先触发。
2. **顺序命令（无timestamp）仍然从上到下执行**：适合写开场铺垫、过场对话。
3. **时间戳命令和顺序命令是并行的**：一边跑顺序命令，一边到点触发时间戳命令，互不阻塞。
4. **`performanceDuration` 最好填上**：如果不填，演出会在所有命令跑完后才结束，可能和 BGM 长度不匹配。
5. **没有 `timestamp` 到小数秒的精度需求**：框架使用 `Time.deltaTime` 累加，帧级精度足够。

## 七、事件系统 —— 对接 UI 层

`PerformanceDirector` 提供了 7 个事件委托，用于让外部 UI 层响应演出状态：

```csharp
// 获取导演组件
var director = GetComponent<PerformanceDirector>();

// 监听演出开始
director.OnPerformanceStarted += (scene) => {
    Debug.Log($"演出 [{scene.sceneName}] 开始了");
};

// 监听每一条命令执行（BGMDriven模式下 timestamp 触发的命令索引为 -1）
director.OnCommandExecuting += (index, cmd) => {
    Debug.Log($"正在执行第 {index} 条命令: {cmd.type}");
};

// ★最重要★ 监听对话文字显示（UI层在这里显示文字）
director.OnDialogueDisplay += (speaker, text) => {
    dialogUI.Show(speaker, text);  // 你的UI显示方法
};

// 监听浮空文字显示
director.OnFloatingTextDisplay += (text, pos) => {
    floatingTextUI.Show(text, pos);
};

// ★BGMDriven模式★ 监听BGM进度（当前秒数, 总秒数）—— 接进度条
director.OnBGMProgress += (elapsed, total) => {
    progressBar.fillAmount = total > 0 ? elapsed / total : 0f;
};

// 监听演出正常结束
director.OnPerformanceEnded += () => {
    Debug.Log("演出结束，恢复游戏控制");
};

// 监听演出被中断
director.OnPerformanceInterrupted += () => {
    Debug.Log("演出被中断");
};
```

## 八、API 参考

### PerformanceDirector 主要 API

| 方法 | 说明 |
|------|------|
| `PlayScene(PerformanceSceneData)` | 播放指定演出场景 |
| `Play()` | 播放 Inspector 中拖入的演出场景 |
| `StopPerformance()` | 强制中断当前演出（BGMDriven模式会自动停BGM） |
| `SkipCurrentCommand()` | 跳过当前正在执行的命令 |
| `AdvanceInput()` | 在 WaitForInput 状态下由外部推进 |
| `IsExecuting` | 是否正在执行中（只读属性） |
| `PerformanceElapsedTime` | 演出已运行时间（秒，BGMDriven模式用于进度查询） |
| `PerformanceTotalDuration` | 演出总时长（秒，BGMDriven模式中=performanceDuration） |

### PerformanceSceneData 关键字段

| 字段 | 说明 |
|------|------|
| `syncMode` | 同步模式：`Sequential`（顺序）或 `BGMDriven`（BGM驱动） |
| `performanceBGMResName` | 演出主BGM资源名 |
| `performanceBGMABName` | 演出主BGM所在AB包 |
| `performanceBGMVolume` | 主BGM音量（0~1） |
| `performanceDuration` | 演出总时长（秒），填BGM的实际秒数

### 跳过机制

- 按 **Escape 键 或 Space 键** 可以跳过当前正在执行的命令
- 仅在 `allowSkip = true` 时生效
- `WaitForInput` 状态下不能跳过（需要点击推进），但按了会触发 `AdvanceInput`
- 跳过后会从头重新创建 CancellationToken，确保后续命令正常执行

## 九、常见问题与注意事项

### 角色注册
角色通过 `GameObject` 名字来查找。所以 `PerformanceCommand` 中填写的 `characterName` 必须和场景中角色 `GameObject` 的名字完全一致。

### 背景切换
`BackgroundChange` 命令的资源从 AB 包异步加载。如果 `duration > 0`，会自动做"淡出→换图→淡入"的过渡效果。

### 效果叠加
因为屏幕滤镜、淡入淡出均使用同一个 `filterOverlay`，这两个效果**不能同时使用**——后执行的会覆盖先执行的。如果需要同时生效，建议用 `Parallel` 中的子命令分别设置不同层。

### DOTween 依赖
角色移动/淡入淡出、摄像机运镜、特效过渡都依赖 **DOTween** 插件。确保项目已导入 DOTween。

### UniTask 依赖
整个框架的异步执行基于 **UniTask**。确保项目已导入 UniTask 库。

### 2D 正交相机
这是为 2D 游戏设计的框架。摄像机的 Zoom 通过调整 `orthographicSize` 实现，旋转只绕 Z 轴。

### 模糊效果
当前的模糊实现是简化方案（通过控制一个模糊 Overlay 的透明度）。如果需要真正的高斯模糊效果，需配合 Unity PostProcessing 或自定义 Blur Shader。

### BGMDriven 模式
**Q: 我的歌是4分12秒，演出总时长应该填多少？**  
A: `performanceDuration` 填 `252`（4×60+12）。建议比你歌曲实际时长多留1~2秒，给最后的收尾命令缓冲。

**Q: BGMDriven 模式下，命令的 `delay` 和 `duration` 还生效吗？**  
A: 都生效。`delay` 是顺序命令之间的间隔；`duration` 是动画/效果的持续时间。`timestamp` 只控制命令"何时开始触发"。

**Q: 我想在歌曲结束前2秒自动淡出，怎么做？**  
A: 添加一条 `ScreenFade` 命令，`timestamp = performanceDuration - 2`，`screenFadeAlpha = 1`（全黑）。

**Q: 中途能换BGM吗？**  
A: 可以用 `PlayBGM` 或 `StopBGM` 命令来切换/停止BGM。注意这不会改变演出总时长——演出仍按 `performanceDuration` 或所有命令执行完毕来结束。

## 十、总结：什么时候使用演出框架

```
普通对话、日常信息交代 → 用 StoryPlayer（传统对白系统）

重要剧情、情绪爆发、意识流段落 → 用 PerformanceDirector（本框架）
```

两个系统可以共存。在关键剧情节点切换到演出模式，日常对话使用对白模式。通过事件系统，它们甚至可以无缝衔接——一段演出结束后触发下一段对白。
