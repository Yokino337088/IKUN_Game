## 二、带动画角色的适配说明

### 2.1 自动支持机制

代码已自动适配带动画的角色预制体，无需额外修改。

**工作原理**：

当演出命令执行 `SetExpression`（切换角色姿态）时，系统会：

1. **优先尝试加载 GameObject 预制体**（带动画）
2. **保存旧实例的位置、旋转、缩放**
3. **销毁旧实例，实例化新预制体**
4. **自动启用 Animator**，播放默认动画
5. **如果预制体加载失败，回退到 Sprite 切换**

### 2.2 角色预制体规范

你的角色预制体需要遵循以下结构：

```
爱坤_角色预制体
├── Transform
├── SpriteRenderer
├── Animator (可选，带动画时添加)
│   └── AnimatorController (包含默认动画状态)
└── 其他组件（Collider等）
```

### 2.3 Animator设置建议

确保Animator控制器包含一个默认状态（Entry直接连接的状态），该状态会在预制体实例化后自动播放。

| 状态名 | 用途 |
|---|---|
| `Idle_Float` | 水下漂浮待机（默认进入） |
| `Fall_Free` | 自由坠落（默认进入） |
| `Lie_Down` | 躺卧（默认进入） |
| `Sit_Up` | 坐起（默认进入） |
| `Stand_Up` | 站立（默认进入） |

### 2.4 关键代码修改

[PerformanceCharacter.cs](../Scripts/剧情演出/PerformanceCharacter.cs) 的 `SetExpression` 方法已更新：

```csharp
// 尝试加载预制体（带动画）
GameObject prefab = await ABResMgr.Instance.LoadResAsync<GameObject>(abName, spriteName);
if (prefab != null)
{
    // 保存旧状态并实例化新预制体
    // ...
    
    // 如果有Animator，自动播放默认动画
    var animator = newGO.GetComponent<Animator>();
    if (animator != null)
    {
        animator.enabled = true;
    }
    return;
}

// 回退到Sprite切换（无动画）
Sprite newSprite = await ABResMgr.Instance.LoadResAsync<Sprite>(abName, spriteName);
// ...
```

## 三、修改步骤

### 步骤1：替换占位预制体

1. 删除 `Assets/资源统一放置点/游戏物体/第四章物体/剧情/` 下的占位预制体
2. 将正式角色预制体放入该目录
3. 确保预制体名称与演出命令中的角色名一致

### 步骤2：打包AB资源

将所有资源打包到正确的AB包中：

| 资源类型 | AB包名 | 资源名示例 |
|---|---|---|
| 角色预制体 | `chapter_four` | `爱坤_水下漂浮` |
| 背景Sprite | `chapter_four` | `水下_深蓝` |
| BGM | `music_four` | `Washed Away` |
| 音效 | `sound_four` | `低频冲击` |

### 步骤3：配置Animator（如果有）

确保每个角色预制体的Animator控制器包含默认动画状态。

### 步骤4：测试演出

在Unity编辑器中运行 `第四章剧情演出.unity` 场景，验证：
- 角色切换时动画是否正常播放
- 位置是否正确保留
- 演出时序是否正确

## 四、注意事项

1. **AB包名称必须严格匹配**：`chapter_four`、`music_four`、`sound_four`
2. **资源名必须严格匹配**：演出命令中的资源名与AB包中的资源名必须一致
3. **角色名约定**：演出中角色名固定为 `爱坤`，预制体注册时使用此名称
4. **SpriteRenderer层级**：背景层级设置为0，角色层级设置为10
5. **UI层级**：UI画布层级应高于角色，确保对话文字显示在最上层
6. **动画状态机**：确保Animator有默认进入状态（Entry连接的状态）
